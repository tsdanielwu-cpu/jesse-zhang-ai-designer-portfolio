# 饭困完整高保真原型网页化设计

## 目标

将 Figma 文件“AI 餐饮决策助手”中 `高保真原型` 页面完整转译为作品集网页内可操作的 React 原型。实现以分享原型的起点 `917:1421` 和 Figma Reaction 连线为唯一流程依据，不再根据页面名称、截图位置或现有简化版本推测交互顺序。

实现范围包括：

- `Section 2`（`917:1420`）内全部顶层高保真画板、覆盖层和可交互状态。
- `Section 3`（`1262:5122`）内的 `UI KIT`（`915:1836`）及相关可复用组件。
- 从 Section 2 原型连线可到达的 Section 2 外部页面，包括必要的过渡、成功、加载或异常状态。
- 分享原型中从 `917:1421` 出发的全部可达流程。

不包含真实账号、真实支付、真实外卖平台、真实定位、服务端推荐或多人实时同步；这些行为使用确定性的本地演示数据表达。

## 采用方案

采用“完整原生网页重建”，不使用 Figma iframe，也不使用整页截图加点击热区。

原因：

- 页面、组件和状态均为真实 HTML/React，可维护、可访问并能融入作品集。
- 交互不依赖 Figma 登录状态或外部网络。
- 能严格复用 UI KIT，并对原型连线进行自动核对。
- 访客既能正常操作完整流程，也能通过页面索引查看任意画板。

## 信息来源与优先级

发生冲突时按以下顺序处理：

1. 分享原型中的 Reaction、起点和 Flow 定义。
2. 单个画板的 `get_design_context` 高保真数据和截图。
3. UI KIT 中的组件、变体、属性与原始 SVG/位图素材。
4. Section 2 画板在画布上的空间排列。
5. 现有网页实现；仅作为项目技术栈与作品集外壳参考，不作为交互依据。

## 页面与流程模型

先读取 Section 2 顶层画板清单，再遍历全部具有 Reaction 的节点，生成两份机器可读数据：

- `screenManifest`：画板 ID、名称、尺寸、所属 Flow、用途、入口条件。
- `prototypeGraph`：源节点、触发方式、动作、目标画板、导航类型、转场与覆盖层位置。

React 运行时使用显式状态机：

- `currentScreenId` 表示当前 Figma 画板。
- `history` 保存真实导航堆栈，返回按钮不再硬编码目标。
- `overlayStack` 表示条件编辑、搜索等 Figma Overlay。
- `session` 保存登录表单、选餐条件、当前场景、选择分类、推荐批次、菜品规格、购物车、口味档案和饭局状态。
- 每个交互控件绑定到其 Figma 源节点 ID，跳转目标来自 `prototypeGraph`。

起点固定为 `917:1421`。登录、注册、首页、历史侧栏、外卖、到店、多人饭局、推荐结果、菜品详情、店铺详情、购物车、个人中心和口味档案等流程必须从真实连线到达。

## 代码结构

现有单文件 `FankunPrototype.jsx` 将拆分为边界清晰的模块：

```text
src/fankun/
  FankunPrototype.jsx        原型外壳、状态机和导航堆栈
  prototypeGraph.js          Figma 画板与 Reaction 映射
  screenManifest.js          全画板清单与 Flow 分组
  demoData.js                本地演示数据
  components/                由 UI KIT 转译的共享组件
  screens/                   按流程拆分的页面组件
  icons/                     Figma 原始 SVG 图标映射
  fankun.css                 原型专用样式与设计变量
```

页面按功能域拆分，而不是把 53 个页面重新堆回一个超大组件。重复页面状态通过共享组件和数据差异表达；每个 Figma 顶层画板仍有唯一 `screenId` 和可直接访问的呈现结果。

## UI KIT 与视觉规则

- 先读取 UI KIT 中的组件和组件集，建立组件名称、变体和使用位置清单。
- 状态栏、Home Indicator、顶部栏、底部导航、输入框、按钮、标签、推荐卡片、店铺卡片、条件卡片、列表项和覆盖层均复用共享组件。
- 所有可见 SVG 和位图从 Figma 下载到 `public/assets/projects/fankun/prototype/`，代码不得引用临时 Figma URL。
- 不使用 Emoji、Unicode 符号或自绘近似图标替代 Figma 图标。
- 保留 393 × 852 的基准画板比例，在桌面作品集内显示为手机原型；小视口允许等比缩放，但不改变内部布局逻辑。
- 色彩、字号、行高、间距、圆角、投影和图片裁切以单画板设计上下文为准。

## 原型页面索引

在手机原型外提供一个折叠式“原型页面索引”：

- 按 Figma Flow 和功能域分组列出所有顶层画板。
- 点击后直接切换到对应 `screenId`，用于作品集讲解和逐页验收。
- 直接跳转不会改变页面的真实交互连线；点击“重新开始”始终回到 `917:1421`。
- 当前画板显示 Figma 名称和节点 ID，方便与设计稿核对。

## 数据与行为

- 登录与注册只校验必填字段并进入 Figma 指定目标，不传输数据。
- 推荐、换一批、菜品规格和购物车使用本地固定数据，确保演示可重复。
- 多人饭局使用本地参与者和投票状态，表现完整操作反馈，不模拟网络同步。
- 搜索、历史记录、口味档案和条件编辑保留可见状态变化。
- Figma 中没有 Reaction 的视觉节点不擅自增加新跳转。
- Figma 中指向同一目标的多个入口必须保持一致。

## 动效

- `SMART_ANIMATE`、`DISSOLVE`、覆盖层和滚动行为按原型数据映射为 CSS/React 转场。
- 动效只使用 opacity 与 transform 等高性能属性。
- 遵守 `prefers-reduced-motion`，减少动效时仍保持流程可用。
- 若原型连线包含 Section 2 外的过渡页，则实现为独立状态，不用延时动画直接跳过。

## 异常与降级

- 缺少目标节点的 Reaction 在开发模式显示诊断提示，并保持当前页面，不跳到猜测页面。
- 缺失素材显示具有节点 ID 的占位提示，验收前不得保留占位。
- 页面索引和正常 Flow 均可从异常状态回到起点。
- 表单不会向第三方或服务器发送数据。

## 验收与测试

### 结构验收

1. Section 2 顶层画板数量与 `screenManifest` 一致。
2. UI KIT 可复用组件均有对应 React 组件或明确的组合映射。
3. 所有 Reaction 的目标节点存在；覆盖层与普通导航类型没有混淆。
4. 所有代码引用的 Figma 素材均为本地文件且 HTTP 返回 200。

### 流程验收

1. 从 `917:1421` 开始逐条执行分享原型中的 Flow 2–5。
2. 登录、注册、首页、外卖、到店、多人饭局、购物车、个人中心等分支均能到达。
3. 前进、返回、底部导航、覆盖层打开/关闭与 Figma 一致。
4. 页面索引能访问每个顶层画板，并能重置回起点。

### 视觉验收

1. 每个功能域至少选择一个代表画板与 Figma 截图并排核对。
2. 检查图标、文字、卡片顺序、图片、圆角、间距和底部安全区。
3. 桌面作品集视口和缩窄视口均无裁切、错位或水平溢出。
4. 浏览器控制台无 React、资源或可访问性错误。
5. Vite 生产构建通过。

## 完成定义

只有同时满足以下条件才算完成：

- Section 2 全画板已登记并可在网页中访问。
- 从分享原型起点出发的全部连线均已实现或被明确记录为无目标动作。
- UI KIT 已转译为共享组件，页面不再使用错误的临时图标。
- 所有核心 Flow 经浏览器实际点击通过。
- 静态 19 页项目长图仍保留在交互原型之后。
